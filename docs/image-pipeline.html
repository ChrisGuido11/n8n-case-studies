Image / moodboard pipeline

What I build for a client: a batch moodboard from a brief that fails loud instead of shipping a pretty wrong board.

The job

A merchandising or creative team needs a set of images from a written brief — not a chatbot that “tries its best.” The workflow takes the brief, calls the image API, and returns a board or a stop. Close-enough is a defect.

Failure paths I treat as bugs

  • Model ID 404. If the model is gone, the run stops. I do not silently fall back to a different model that looks close.
  • Negative prompts that no-op. Some APIs ignore the negative prompt and still return 200. I check that the constraint was applied, or I mark the output unconstrained.
  • Auth in the header field. I never type Bearer into a header. HTTP nodes already add it. A double prefix is a silent 401. Credentials stay in credentials — not in a node someone will export.

What the client sees

Either a board that matches the brief, or a named failure: missing model, ignored negative, or auth that never left the credential store. No mystery image that “almost” worked.

Clean-room site. No client files, workflow JSON, or keys.
