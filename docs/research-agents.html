Research agents

What I build for a client: agents that only write from URLs they actually fetched.

The job

A research pass that takes a list of sources, reads them, and returns notes with citations. The model does not get to invent a link because the prompt sounded like a bibliography.

The = bug

In n8n, ={{ $json.url }} is an expression. Leave off the = and the node sends the literal characters {{ $json.url }}. The model then “researches” a template string and invents links to look helpful. I treat that as a wiring defect, not a model quirk. The HTTP or LLM node must receive the resolved URL, or the run stops.

Count in / count out

If twelve URLs go in, twelve come back accounted for — kept, dropped with a reason, or failed. A thirteenth citation that was never fetched is a defect. A silent drop is a defect. The client should be able to tick the list.

What the client sees

A note file plus a ledger: in, out, dropped, failed. Invented citations do not ship.

Clean-room site. No client files, workflow JSON, or keys.
